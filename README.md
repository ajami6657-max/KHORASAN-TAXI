# تاکسی زعفران | ZAFFRAN TAXI

**شعار:** از روستای تو تا مقصد تو

سامانه حمل‌ونقل هوشمند با شروع از **خراسان جنوبی**؛ شامل سفر شهری، روستا ↔ شهر، بین‌شهری، سرویس ویژه بانوان، پیک، وانت و یدک‌کش.

> هدف این مخزن ساخت محصول واقعی، امن و قابل توسعه است. قابلیت‌هایی که هنوز به سرور یا سرویس بیرونی متصل نشده‌اند، آزمایشی هستند و هرگز سفر یا پرداخت واقعی را وانمود نمی‌کنند.

## اجزای محصول
- Passenger App: اپلیکیشن مسافر
- Driver & Provider App: اپلیکیشن راننده و ارائه‌دهندگان خدمات
- Admin Panel: پنل مدیریت وب
- Backend API: احراز هویت، سفر، قیمت‌گذاری، پرداخت و موقعیت
- Persian AI Assistant: دستیار فارسی با استقرار قابل‌دسترسی از شبکه ایران، پس از آزمون
- Maps: نقشه، مکان‌یابی و مسیریابی

## محدوده شروع
استان خراسان جنوبی؛ شهرستان‌ها، شهرها و روستاها از پنل مدیریت قابل تعریف خواهند بود. گسترش به استان‌های دیگر پس از آماده‌شدن عملیات و پوشش راننده انجام می‌شود.

## جهت فنی
- Mobile: Flutter برای کد مشترک Android و iOS
- Backend: FastAPI + PostgreSQL/PostGIS
- Realtime: WebSocket با راهکار جایگزین برای اینترنت ضعیف
- Admin: پنل وب واکنش‌گرا
- CI: GitHub Actions برای Android؛ ساخت و امضای iOS نیازمند macOS/Xcode و گواهی‌های اپل است.

**وضعیت مهاجرت:** مخزن اولیه با Kotlin/Jetpack Compose برای Android ساخته شده است. نسخه Flutter باید در کنار نمونه فعلی ایجاد و آزمایش شود؛ نمونه فعلی تا زمان موفقیت ساخت و تست Flutter حذف نمی‌شود.

## ساخت APK نمونه فعلی
با هر commit روی `main`، گردش‌کار Android CI تلاش می‌کند نسخه Debug نمونه Kotlin را بسازد. APK در بخش Artifacts اجرای GitHub Actions قرار می‌گیرد.

## وضعیت قابلیت‌ها
اسکلت اولیه Android و مستندات معماری موجود است. درخواست سفر واقعی، پرداخت، GPS زنده، احراز هویت برخط و هوش مصنوعی متصل تا زمان پیاده‌سازی و آزمایش یکپارچه، عملیاتی محسوب نمی‌شوند.

## امنیت و امور مالی
- کلید API، رمز عبور و کلید امضای انتشار را در Git ثبت نکنید.
- اطلاعات هویتی رانندگان باید رمزگذاری و با دسترسی محدود نگهداری شود.
- تأیید AI فقط کمک‌تصمیم است و جای بررسی انسانی مدارک حساس را نمی‌گیرد.
- درگاه منتخب: آسان پرداخت (آپ)، مشروط به پذیرندگی، قرارداد، مستندات رسمی و آزمون sandbox.
- دو روش تسویه راننده طراحی می‌شود: درخواست تسویه لحظه‌ای و تسویه دسته‌ای روزانه؛ انتقال واقعی فقط پس از تأیید API و قرارداد بانک/ارائه‌دهنده فعال خواهد شد.
- ثبت سهم راننده و کمیسیون در دفترکل داخلی به‌معنای واریز بانکی نیست؛ وضعیت درخواست واریز تا تأیید نهایی بانک جداگانه نمایش داده می‌شود.
